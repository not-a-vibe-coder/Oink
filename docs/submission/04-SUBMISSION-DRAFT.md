**Status:** local draft. Not uploaded. Founder facts, hosted URLs, narration and live validation are still required.

**Product:** Oink Flow + Bell

**One line:** A USDC income planner that fills your cash reserve first and checks tokenized-stock purchases before you approve them.

**Problem and customer:** USDC-paid freelancers who already save and invest must repeatedly decide how much income stays liquid and manually review investment execution. This problem statement has not yet been validated through interviews.

**Product:** Referenced payment links, finalized payment verification, exact cash-first allocation, independently tracked stock orders, explicit execution policies, local wallet signing, durable attempts, reconciliation, retry/cancellation, and separate payment/purchase receipts. Curated SPYx, AAPLx, and NVDAx support uses existing tokenized instruments; Oink does not issue equities.

**Infrastructure:** Solana SPL USDC, Token-2022 xStocks, Jupiter Swap v2 build instructions, browser Ed25519 signing, Bun/Express/PostgreSQL, TanStack Start/React. Existing Oink password/TOTP encrypted wallet remains the custody foundation. Bell users supply SOL for fees.

**Evidence:** Automated checks exercise real HTTP and SQL logic with mocked chain evidence. Read-only $10 live routes were observed for all three assets. A clearly labelled browser simulation has desktop/phone screenshots and a silent recording. No mainnet fill, user traction, revenue, reference-price premium validation, or claimed execution savings are demonstrated.

**Go to market:** Recruit a small consented cohort of USDC-paid freelancers through founder relationships. Observe the existing payment workflow, test the next actual payment, and invite repeat use. Test partner distribution through contractor/payment platforms after customer demand is established. No paid acquisition or partnerships are claimed.

**Business model hypothesis:** Paid cash/allocation tools or platform integrations. Execution fees would need transparent user disclosure and separate implementation; Bell currently encodes zero platform fees. Pricing remains unvalidated.

**Why this could become a business:** A recurring income workflow could create recurring usage and platform distribution. The pilot must establish that users want the workflow enough to return and pay. This is a hypothesis, not a market-size estimate or prize prediction.
