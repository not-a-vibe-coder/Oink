# Development and reuse disclosure

Oink Flow + Bell builds on an existing Oink repository rather than starting from a blank application. Oink itself follows the TENDER porting plan. The founder must confirm the provenance, ownership, prior competition submissions, and funding history of that earlier work.

## Existing before the Flow/Bell extension

At revision `64b3d01`, Oink already contained browser wallet crypto, password/TOTP authentication and recovery, local key session, tag/identity work, portfolio mix, transfer/invoice services, fee-payer plumbing, Solana/Jupiter integration, token registry, frontend design, and documentation. Flow/Bell reuses the encrypted wallet, signing helper, account sessions, RPC connection, curated token metadata, and Oink visual language. Historical landing claims and legacy mix features are not evidence of Bell execution.

Those dates fall inside the announced September 14–October 12 competition window, but imported or earlier source development is not established by commit timestamps. Disclose it rather than treating all source as newly authored competition work. Generated code and AI-assisted work should be described honestly when the portal requests development details.
